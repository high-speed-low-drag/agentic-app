## Fix
1. **Fallback** (`frontend/src/components/network/NetworkDiagram.tsx`): apply the nearest-bus-node fallback (within
   7 rendered px) to every tap whose target is **not itself selectable**. That covers the background, branch edges as
   today, appliance stub edges (`edge.stub`), labels, hubs if they aren't selectable, and anything else non-selectable.
   A tap directly on a selectable symbol or appliance (generator, shunt, transformer overlay, load glyph) still
   selects that element. Keep programmatic taps without a position skipped, as today.
2. **Layout-ready marker:** set `data-layout-ready="1"` on the diagram root after the layout and fit finish
   (`layoutstop` plus any fit or animation). Reset it while a re-layout runs.
3. **Test robustness** (`node-size.spec.ts`, and any other spec using the same pattern; check `helpers.ts`):
   - wait for `data-layout-ready="1"`;
   - compute the click point **immediately** before each click;
   - replace the bare `page.getByText(a.name).first()` checks with checks scoped to the details panel;
   - make the "clear selection" click target a point that's verified empty (no element within 10 px), or use a
     programmatic unselect, instead of a fixed top-left + 4 px.
4. **Sweep test:** add a test that clicks Rail B 5 px off-centre in 8 directions (0°, 45°, …), at zoom 1 in both the
   editor and the snapshot. Every click must select `node:0`. Also add one click directly on Rail B's shunt or
   generator symbol, which must select that appliance, not the node.
5. **Reproduce the CI conditions as far as possible:** run the e2e suite with `CI=1`. If you can, also try a viewport
   or device-scale-factor matching CI: Linux headless Chromium uses DPR 1 and 1280×720 unless the config sets
   otherwise, so check `playwright.config.ts`. Confirm the old code fails the new sweep test locally before the fix, so
   it's a real regression test. Report whether it did.

## Context
`frontend/src/results/views/NetworkSnapshotView.tsx` defines its speeds as `SPEEDS = [{600,'1×'},{250,'2×'},{80,'4×'}]`,
in ms per timestep. These aren't proportional. Playback advances only when `!snap.isFetching`, so it never skips frames.
`useSnapshot(runId, t)` is in `frontend/src/api/hooks.ts` and uses `keepPreviousData`.

## Change
1. **Speed table:** make the speeds proportional to 1× = 600 ms per step, with labels 1×, 2×, 4×, 8×, 16×
   (600, 300, 150, 75, 37.5 ms). Generate the table from one base constant and a list of multipliers, and export it for
   testing, e.g. `playbackSpeeds()` in a small module. Keep the default at 2×.
2. **Prefetch:** while playing, prefetch the next K snapshots with react-query `queryClient.prefetchQuery` using the same
   query key as `useSnapshot`, wrapping at the end of the run. Pick K from the speed: about 2 at 1×/2× and about 8 at
   16×. Make sure the prefetched data is fresh enough to be reused: set a sensible `staleTime` for snapshots, since run
   results never change.
3. **Timing:** keep the "never skip a frame" rule. Use a timer that targets the ms per step, measured from when the
   previous frame was shown, so fetch time doesn't add to the interval when data is already cached. If the next frame
   isn't ready, wait for it; never skip.
4. **Speed control:** the Segmented control must still fit with 5 options at about 1280 px, and wrap cleanly on narrower widths.

## Tests

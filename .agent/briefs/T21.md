## Build `.github/workflows/ci.yml`
- **Triggers:** `pull_request` (branches: main) and `push` (branches: main). Use `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`.
- **Permissions:** `contents: read` only. No secrets. Do not use `pull_request_target`.
- **Job:** a single job on `ubuntu-latest`, `timeout-minutes: 20`.
- **Steps:**
  1. `actions/checkout`, pinned to a released major version (v4 or newer).
  2. `astral-sh/setup-uv`, released version, with caching enabled and keyed on `backend/uv.lock`. Python comes from
     `requires-python` (3.12) via uv. Make sure `uv sync` installs 3.12; set `UV_PYTHON=3.12` if needed.
  3. `actions/setup-node`, with a node version matching local development (local is Node 26; check that the frontend
     tooling works on the chosen version) and npm caching keyed on `frontend/package-lock.json`. Prefer adding
     `frontend/.nvmrc` or an `engines` field and using `node-version-file`, so local and CI share one source of truth.
  4. Install: `cd backend && uv sync --frozen`, and `cd frontend && npm ci`. Consider adding a `make ci-install`
     target, or making `make install` use `npm ci` when `CI` is set; keep `make install` working locally either way.
  5. `make check`.
  6. `cd frontend && npx playwright install --with-deps chromium`.
  7. `make e2e`.
  8. On failure, upload `frontend/playwright-report/` and `frontend/test-results/` with `actions/upload-artifact`
     (released version, `if: failure()`, retention about 7 days).
- **Playwright config:** check `frontend/playwright.config.ts` for CI-friendliness:
  - `forbidOnly: !!process.env.CI`;
  - `retries: process.env.CI ? 1 : 0`, so a single flaky test doesn't fail the build but still shows in the report;
  - `reuseExistingServer: !process.env.CI`;
  - a reasonable `workers` setting;
  - an HTML reporter on CI, plus `list` output;
  - webServer timeouts long enough for a cold `uv run`.
  Keep local behaviour unchanged.
- Check that nothing in `make check` or `make e2e` depends on the local machine: absolute paths, the `workspace/` directory,
  or a running dev server. The e2e global teardown already removes its temp workspace.
- **README:** a short "CI" section saying what runs and how to reproduce it locally (`make check && make e2e`).

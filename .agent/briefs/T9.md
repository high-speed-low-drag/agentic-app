## Bug
After editing equipment in the Network tab table (per-case `network_overrides`, from T6), other screens still show the
network file's values. Two places are known:
1. The Profiles tab target list: `frontend/src/pages/case-editor/ProfileAssignmentCard.tsx` builds `candidates` from the raw
   `topology.appliances` with `hint: fmtPowerW(x.p_specified)`.
2. The diagram's details panel, `frontend/src/components/network/ElementDetails.tsx`: "P specified", "Q specified" and "In service".

Simulation results are correct, because the backend applies the overrides. This is a display bug only.

## Fix
- **Helper:** in `frontend/src/components/network/overrides.ts`, add one pure helper, e.g.
  `effectiveTopology(topology, overrides)`. It returns a topology whose appliances (`p_specified`, `q_specified`,
  `in_service` from `status`), branches (`params`, plus `in_service` from from/to status) and sources (`params`) reflect
  the overrides. It also returns, per element, which fields are edited and their file values, for example through a
  lookup `isEdited(kind, id, field)` / `fileValue(...)`. Memoise it at the case-editor level.
- **Use it** wherever the case editor shows equipment values: the profile assignment card's candidates and the
  "All <component> (N)" counts, the element details panel, and anything else that reads topology values in the case
  editor. Search for `p_specified`, `q_specified`, `in_service` and `params`. Use the T6 overrides helpers for unit handling.
- **Profile target list:**
  - An edited element shows its current value with a small amber "edited" marker (reuse the T6 warning tokens),
    and a tooltip with the file value.
  - An element that is out of service (from an edit, or from the file) shows "out of service" in muted text and stays
    selectable.
- **Details panel:** edited values get the same amber marker and a tooltip with the file value.
- **Out of scope:** results views, which use the run's frozen case. Only change them if they show topology base values
  that should come from the frozen run case. If you find such a place, note it rather than expanding scope.

## Tests

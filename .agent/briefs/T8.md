## Why
The automatic jump to the table on a diagram click "ruins the view". The user wants to stay on the diagram, and uses
the details panel's "Edit in table" button when they want to edit.

## Change
Update `selectionEffects` in `frontend/src/components/network/selection.ts` and its callers (`useNetworkSelection.ts`,
`ElementTable.tsx`):
- **Diagram click (`source: 'diagram'`):**
  - The element is selected and the details panel fills, as today.
  - No page scroll, no row flash, no filter clearing, no "Filters cleared" note.
  - Quietly, the table switches to the element's tab and highlights the row. If the row is visible under the current
    filters, scroll it into view inside the table's own scroll container only, by setting the container's
    scrollTop/scrollLeft. Never call `scrollIntoView` here, because it can scroll the page.
  - If the filters hide the row, leave them alone; the row is simply not shown.
- **"Edit in table" (`source: 'details'` reveal):** keep the full T7 behaviour: page scroll to the row, flash, filter clearing
  with the note, and the P input ready to edit.
- **Table row click → diagram centring:** unchanged.
- Remove or keep "Back to diagram", whichever is cleaner. Keeping it is fine, since it still helps after "Edit in table".

## Tests

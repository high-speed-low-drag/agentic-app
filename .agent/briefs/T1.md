# T1: Backend brief

Build the Python backend of GridSim in `backend/` ONLY (the frontend is in `frontend/`, owned by T2). Do not git commit.
Keep `.agent/progress/T1.md` updated after every sub-step: checklist, verify status, decisions, and a precise `Next step:` line.
(Legacy name from the first run: `.agent/progress/backend.md`. If that file exists, read it.)

Binding docs: `docs/architecture.md`, `docs/api-contract.md` (the frontend codes against them exactly).

Environment: uv project, Python 3.12, package `gridsim` in `backend/src/gridsim/`. Deps: power-grid-model 1.13.x, fastapi,
uvicorn, pydantic v2, pandas, pyarrow, pyyaml, typer; dev deps: pytest, httpx, ruff. Remove `readme` from pyproject; script
`gridsim = "gridsim.cli:app"`. Samples (PGM JSON, MPL-2.0, from PGM repo tests/data/power_flow): `samples/networks/vision_mv.json`
(names in `Name` field) and `ieee14.json`. Add an attribution README.

Modules:
- `models.py`: Pydantic API models per the contract.
- `registry.py`: generic Registry.
- `networks/`: NetworkSource protocol (`list_items`, `load`) with `sample` and `upload` sources. Document how to add a lakehouse source.
- `profiles/`: generators `constant`, `residential_load`, `commercial_load`, `pv`, `ev_charging`, `csv`. Each has a Pydantic Params model
  (provides `params_schema`) and `generate(timestamps, n_elements, params) -> (n_steps, n_elements)` multipliers. Generators are
  deterministic per seed, vary per element, and are vectorised.
- `studies/timeseries_powerflow`: builds the PGM batch update for sym_load/sym_gen (scale/add, in assignment order).
- `engine/pgm_adapter.py`: chunked `calculate_power_flow(update_data, continue_on_batch_error=True)` with progress and cancel;
  failed timesteps become NaN.
- Results: long-format parquet per node/branch/source/appliance, plus `summary.json` (KPIs, extremes, contiguous violation
  episodes). `results.py` serves the timeseries/envelope/heatmap/snapshot queries.
- `workspace.py`: file store under `GRIDSIM_WORKSPACE` (default `<repo>/workspace`). Seed a demo case "Vision MV – summer week".
- `runner.py`: background thread pool, run.json state, cancellation, SSE subscriptions. Marks stale runs failed on startup.
- `api/`: `create_app()` with routes under `/api`. CORS for :5173. SSE events `progress`/`done`. Serves `frontend/dist` with SPA fallback.
  Every route has a `response_model` and a clean operation id.
- `cli.py`: typer commands `serve`, `run <case>`, `cases`, `export-openapi <path>`.

Tests: generators, registry, network loading, single-step batch result == non-batch result, small end-to-end study,
violation episodes, and API tests for every contract route (including uploads and SSE). Ruff: line-length 100, py312.
Performance: a 1-year 15-min vision_mv run should finish well under a minute.

Done check: `cd backend && uv run pytest -q && uv run ruff check . && uv run ruff format --check .`, plus `gridsim serve` working.

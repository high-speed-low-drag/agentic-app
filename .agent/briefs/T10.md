## Part A: generic_branch editable fields
Context: IEEE 14 (`backend/src/gridsim/samples/networks/ieee14.json`) has only `generic_branch` elements, and none of them
has `sn`. PGM therefore reports loading = 0 for all of them. See GitHub issue #1, which stays open for the rest of its scope.
`backend/src/gridsim/networks/editable.py` has no `generic_branch` entry, so the Branches tab shows nothing editable on IEEE 14.

1. **Editable fields:** add `generic_branch` to `EDITABLE_FIELDS`:
   - `sn`: "Rated power", MVA, scale 1e-6, min 0
   - `r1`: R1, Ω
   - `x1`: X1, Ω
   - the existing `*_BRANCH_STATUS` in-service toggle
2. **Missing file values:** the file has no `sn`, so it deserialises as NaN. Make sure the topology `params` send it as JSON
   `null`, never NaN, which isn't valid JSON. Check every place NaN could leak, and make overrides validation accept
   setting a value whose file value is null.
3. **Frontend, missing values:**
   - When the file value is null, the cell shows an empty input with a "—" placeholder (not 0).
   - Once edited, it shows "was not set", and the tooltip says "File value: not set".
   - Revert restores the empty state.
   - The `EditedMarker` and details-panel tooltips handle null the same way.
4. **Backend tests:**
   - On IEEE 14, overriding `sn` = 100 MVA on one generic branch gives loading equal to max(s_from, s_to) / 100e6 for
     that branch. Check PGM's definition and compare with tolerance.
   - Switching a generic branch out of service gives about zero flow on it.
   - The topology JSON contains `null` (not NaN) for missing `sn`.
   - The editable-fields endpoint includes `generic_branch`.

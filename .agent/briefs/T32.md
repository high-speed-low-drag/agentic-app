## Goal
The case-editor network diagram gets an **edit mode** for adding equipment by clicking on it, reusing T31's data model
(`NetworkAddition`, incl. its `position` field), helpers (id allocation, `withAdditions`) and the reusable add form.
The diagram is `frontend/src/components/network/NetworkDiagram.tsx`, used through `NetworkExplorer` and
`ExpandableNetwork`.

## Interactions
- An edit-mode toggle on the case-editor diagram (only where the case is editable, not on run/result views). Show the
  current tool clearly (e.g. a small toolbar: Node / Line / Link / Load / Generator / Shunt, or a mode + context
  choice — your call, keep it simple and discoverable) and a hint line ("Click empty canvas to place a node", "Click the
  first node", "Click the second node — Esc cancels").
- **Place node:** click on empty canvas → the add form opens pre-filled with component `node` and `position` = the
  click position in diagram (model) coordinates, not screen pixels.
- **Draw line/link:** click a first node (highlight it, optionally a rubber-band edge following the pointer), then a
  second node → the add form opens pre-filled with `from_node`/`to_node`. Clicking the same node again or pressing
  Esc cancels a half-drawn line.
- **Attach appliance:** click a node with the load/generator/shunt tool → add form pre-filled with that node.
- Cancel in the form adds nothing; Save appends the addition exactly like the table's Add flow (unsaved-changes and
  save flow unchanged).
- Edit mode also works in the expanded overlay (`ExpandableNetwork`), and Esc cancels there too without closing the
  overlay when a line is half drawn (first Esc cancels the line; a further Esc may close the overlay as today).
- Normal (non-edit) clicks keep selecting elements as today.

## Placement (no full relayout)
- Store the click position in `NetworkAddition.position`. Nodes added from the table (no position) get a position
  computed near their connected neighbours (or a free spot) — pure helper with tests.
- Adding an element must not re-run the full layout: existing nodes keep their positions; new nodes go to their stored
  position. Use preset positions for known nodes / keep the cytoscape instance's current positions, and only lay out
  what has no position. Appliances follow the existing rendering of loads/gens on nodes.
- The snapshot / result views of a run of that case use the stored positions too (they come from the frozen case's
  additions).
- Dragging existing nodes is not required. Dragging an added node to update its `position` is a nice-to-have only.

## Tests

## Goal
In the case editor's Network tab, the element table becomes editable per cell, like a spreadsheet. Edits are stored as
**per-case overrides** on top of the unchanged network file. A changed cell is highlighted amber, shows "was <file value>",
and has a per-cell revert button. The table header offers "N changes", a "Changed only" filter and "Revert all".
Changed elements are also marked in the network diagram.

## Backend
- **Editable fields registry** (e.g. `backend/src/gridsim/networks/editable.py`): per PGM component, list the fields that can be
  overridden, each with a display unit and scale (W→MW, var→Mvar, VA→MVA), a kind (float/int/bool) and optional min/max.
  - sym_load and sym_gen: `p_specified`, `q_specified`, `status`
  - line: `r1`, `x1`, `c1`, `i_n`, `from_status`, `to_status` (show the two statuses as one "in service" toggle that sets both)
  - transformer: `sn`, `tap_pos` (int, within tap_min..tap_max), `from_status`/`to_status` (same toggle)
  - link: the same toggle only
  - source: `u_ref`
  - generic_branch and others: none in v0
  Expose it as `GET /api/networks/editable-fields` → `{component: [{field, label, unit, scale, kind, min, max}]}`.
- **Topology**: the topology response includes, per element, a `params: {field: file_value}` dict with the editable fields' file values.
- **CaseStudy** gets `network_overrides: list[NetworkOverride]` (default `[]`), where
  `NetworkOverride = {component, id, field, value}`, with `value` in SI/PGM units.
- **Applying overrides**: a function copies the loaded input arrays and writes the overrides. It is used by validation and
  by the study before `build_update`, so profiles scale the overridden base values.
- **Validation errors** name the element and field: unknown component, id or field, a non-editable field, out-of-range
  values, and PGM `validate_input_data` failures after overrides.
- The run's frozen `case.json` already contains the overrides. Verify that.
- **Tests**:
  - a lower line `i_n` raises that line's loading
  - a doubled load `p_specified` raises it
  - the frozen case keeps the overrides
  - invalid overrides give clear errors
  - the editable-fields endpoint works
- **Docs and types**: update `docs/api-contract.md`, then run `make types`. The contract drift guards must pass.

## Frontend
- **Table**: `ElementTable` shows the editable fields as columns per tab, using units and scale from editable-fields.
  - Each editable cell is an inline input with a unit suffix. Booleans are a checkbox or toggle.
  - Commit on blur or Enter. Escape cancels.
  - A changed cell gets amber tokens (warning bg/border/text, in light and dark), "was <file value>" underneath, a tooltip
    with the file value, and a revert icon button with an aria-label.
  - Setting a value back to the file value removes the override.
- **Header**: shows "N changes" (per tab and in total), a "Changed only" filter and "Revert all" (with a confirm dialog if there are more than 5).
- **Diagram**: changed elements get a visible marker, e.g. an amber ring or outline.
- **Editor state**: overrides live in the case state, so the existing dirty indicator and Save cover them. Show validation issues as today.
- **Network switch**: changing the selected network clears the overrides, after a confirm if there are any.
- **Tests**: Vitest for override helpers (set, revert, units round-trip). A new Playwright spec:
  - edit a sym_load's P on vision_mv, and check the amber cell, the "was" text and "1 change"
  - save and run, then check the run succeeds
  - revert, and check the cell is back to normal and the count is 0
- **Visual check**: in the built-in browser if available, otherwise with Playwright screenshots. Check light and dark
  mode, and that the table stays usable at about 1280px with the extra columns (it may scroll horizontally).

# T2: Frontend brief

Build the GridSim web frontend in `frontend/` ONLY (the backend is in `backend/`, owned by T1). Do not git commit.
Keep `.agent/progress/T2.md` updated after every sub-step: checklist, verify status, decisions, and a precise `Next step:` line.
(Legacy name from the first run: `.agent/progress/frontend.md`. If that file exists, read it.)

Binding docs: `docs/architecture.md`, `docs/api-contract.md`. The runtime is deterministic: NO chat or AI features in the UI.
It should be a polished, modern engineering tool.

Stack: Vite + React + TS strict, react-router, @tanstack/react-query, ECharts, Cytoscape.js (auto-layout, e.g. fcose or
breadthfirst from the source), Tailwind v4, lucide-react, and your own small component set. Light theme plus dark mode via CSS
variables. Dev server on :5173 with a proxy from `/api` to 127.0.0.1:8000. API types go in `src/api/schema.ts`, fetch calls in
`src/api/client.ts`, hooks in `src/api/hooks.ts`. Add an `openapi-typescript` script `types`.

Pages:
- App shell with sidebar (Cases, Runs) and a health/PGM-version indicator.
- Cases list with create and delete (confirm).
- Case editor with Save, Validate, Run and a dirty-state indicator. Sections:
  - Overview.
  - Network: picker, upload, Cytoscape diagram with a details panel, element tables.
  - Time & calculation: datetime inputs, resolution presets, timestep count, duration presets, method/tolerance/iterations, limits.
  - Profiles: assignment list; generator select; form generated from JSON Schema; targets (all or chosen ids); scale/add mode;
    debounced preview chart; CSV upload with column pick.
- Run page: SSE progress with polling fallback, cancel, then results.
- Results: KPI tiles plus the `RESULT_VIEWS` registry in `src/results/views/index.ts`
  (`{id, title, description?, component: React.ComponentType<{runId, summary}>}`), one view per file, and a README on adding a view.
  Views: VoltageEnvelope, ElementTimeseries, LoadingHeatmap, Violations (tables with click-to-plot), NetworkSnapshot (time slider and play).
- Runs list.

Quality: `npm run build` (tsc -b) passes, `npm run lint` passes, Vitest unit tests pass (`npm run test`).
Responsive, with loading/empty/error states and sensible number formatting.

Done check: `cd frontend && npm run build && npm run lint && npm run test`.

## Context
`frontend/src/components/network/`: `NetworkExplorer.tsx` holds a shared `selected: ElementRef` used by `NetworkDiagram`,
`ElementDetails` and `ElementTable`. `ElementTable` owns its `tab` state, a search box `q`, a "Changed only" filter
(from T6 in-cell editing), and passes `selectedKey` to `Table` only when the tab matches. Nothing scrolls or switches tab today.

## Diagram → table
1. When an element is selected from the diagram (node, branch, appliance glyph, source), the table switches to that element's
   tab. To make that possible, lift the tab state into the explorer or make it controllable.
2. If the search query or "Changed only" would hide the selected row, clear them and show a small dismissable inline
   note, e.g. "Filters cleared to show Load1".
3. Scroll the row into view within the table's scroll container, both vertically and horizontally to the start. Then flash
   it once (about 1 s, using an accent background animation that respects `prefers-reduced-motion`), and keep the normal
   selected highlight afterwards.
4. Scroll the page only as much as needed to make the row visible (`block: 'nearest'`).
5. The selected row shows a small "Back to diagram" link or button that scrolls the diagram back into view.
6. `ElementDetails` gets an "Edit in table" button that triggers the same jump.

## Table → diagram
7. Clicking a row (not an input inside it, so editing a cell must not trigger this) selects the element. If the diagram is
   at least partly in the viewport (use an IntersectionObserver), it animates to centre the element, keeps the zoom unless
   it's very zoomed out, and highlights it with the existing selection style. If the diagram is off screen, don't scroll
   the page; just set the selection.
8. Selecting through the details panel's neighbour links keeps working.

## General
- Keep the selection logic in one small hook or module, e.g. `useNetworkSelection` or `focusElement(ref, source)`, where
  `source` is `'diagram' | 'table' | 'details'`, so each source gets the right side effects without loops.
- Add stable `data-testid`s where needed.
- Apply the same behaviour on the read-only explorer outside the case editor, if it exists (e.g. the results network
  snapshot does not need it).
